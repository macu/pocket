# Notes

The basic concept for this app is that content would be added and organized at the intersection of various generic and specific topic categories. The user would choose a selection of topics when creating a post or exploring the database, and then see content organized under that particular selection. E.g., a particular ship + a particular event = everything people tagged with those combined topics. When searhing, the user would see the top topics associated with those already selected, and would have the option to make the scope more specific or more general, until they find what they're looking for.

```sql
CREATE TYPE post_type AS ENUM (
	'topic',
	'text'
);

CREATE TABLE post (
	id SERIAL PRIMARY KEY,
	parent_post_id INTEGER REFERENCES post (id) ON DELETE CASCADE, -- null for topics
	author INTEGER NOT NULL REFERENCES user_account (id) ON DELETE CASCADE,
	post_type post_type NOT NULL,
	post_subject TEXT COLLATE case_insensitive NOT NULL, -- written story, joke, etc.
	created_at TIMESTAMPTZ NOT NULL
);

ALTER TABLE post
	ADD CONSTRAINT post_parent_post_id_post_subject_key
	UNIQUE (parent_post_id, post_subject);

CREATE INDEX post_subject_fulltext_idx ON post USING GIN (to_tsvector('simple', post_subject));

CREATE TYPE vote_type AS ENUM (
	'upvote',
	'downvote'
);

CREATE TABLE post_topic (
	post_id INTEGER NOT NULL REFERENCES post (id) ON DELETE CASCADE,
	author INTEGER NOT NULL REFERENCES user_account (id) ON DELETE CASCADE, -- pin author's
	topic_id INTEGER NOT NULL REFERENCES post (id) ON DELETE CASCADE,
	vote_type vote_type NOT NULL,
	created_at TIMESTAMPTZ NOT NULL
);
```
